# Guía breve para completar la parte de GitHub

Esta guía acompaña la documentación preparada para la Entrega 4. No reemplaza las acciones reales que debe realizar el estudiante en GitHub.

## 1. Repositorio público
1. Iniciar sesión en GitHub y crear un repositorio nuevo.
2. Usar el nombre `tecnostock-sistema-inventario-ventas` y seleccionar **Public**.
3. Cargar los archivos y carpetas de este paquete, conservando el README como página principal.
4. Copiar la URL pública y reemplazar el marcador de la primera página del informe y de README.md.

## 2. Ramas y commits
Crear ramas secundarias a partir de `main`, por ejemplo:
- `feature/bpmn-registro-ventas`
- `docs/historias-usuario-backlog`
- `docs/indicadores-control`

Realizar cambios pequeños y registrar commits con mensajes como `docs: incorpora diagrama BPMN del registro de ventas`. No inventar commits: deben corresponder a modificaciones reales.

## 3. Pull Request y revisión de pares
1. Abrir un Pull Request desde una rama secundaria hacia `main`.
2. Incluir el objetivo y los archivos modificados.
3. Solicitar revisión a un compañero real.
4. Resolver las observaciones recibidas y esperar una aprobación real antes de fusionar.
5. Guardar el enlace o una captura del PR con la revisión.

## 4. Tablero GitHub Projects
1. Crear un Project de tipo Board.
2. Configurar el campo de estado con `Por Hacer`, `En Progreso` y `Listo`.
3. Crear tres Issues utilizando las historias US-01, US-02 y US-03 de `historias_usuario.md`.
4. Agregar los Issues al Project y actualizar su estado según el trabajo efectivamente realizado.
5. Copiar la URL pública del tablero al informe y al README.

Los estados que aparecen en el CSV son una propuesta inicial para organizar la documentación, no evidencia de implementación del software.
